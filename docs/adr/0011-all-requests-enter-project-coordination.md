# 所有请求先进入项目协调

CLI 和私聊接单由 [ADR 0013](0013-project-group-intake-only.md) 移除。以下保留原决定背景，其余项目归属、GitHub 证据与历史恢复决定继续适用。

2026-11-12，用户明确要求任何项目都由协调者接单，移除 Runtime
自动创建普通执行任务的路线。本决策取代 ADR 0010 中项目可选、未配置项目
继续普通接单的安排，保留协调者和 Worker 复用 Task 执行机制的选择。

GitHub、飞书私聊和 CLI 先保存接单记录。接单记录复用 Task 的来源身份、
输入、附件与请求回执，但没有正式执行能力。只有协调者和已委派成员可以
创建正式 Thread、准备工程资源、投递执行输入或处理原生审批。

协调者通过 `dispatch(intakeTaskId)` 原地接管请求。相较于增加独立的接单
数据库和第二套附件恢复机制，这保留了已有请求编号和材料关联。代价是 Task
记录中需要明确区分接单、执行与等待接管的历史任务。

工程发现仅提供项目候选，不扩大 GitHub 收集仓库。明确配置的项目规则优先，
自动项目按实际目录保存身份，源仓库绑定不得跨项目静默变更。无法确定项目
时澄清，不回退到普通执行。

历史正式任务原地纳入协调，不复制执行者或改变原群、Thread 与资源。
操作员暂停、已有失败与原生审批关联继续保留。工程流程仍由协调者与 Worker
选择 pstack playbook，Runtime 不定义开发、PR、验证或合并阶段。

需求与验收见[统一协调接单规格](../../.scratch/coordinator-only-intake/spec.md)。
