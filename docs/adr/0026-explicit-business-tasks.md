# 业务任务保存显式来源、关联和生命周期

任务优先看板以原始请求、Issue 或协调者目标为业务任务身份。一个业务任务包含多个明确关联的 Worker，协调者显示为负责人。协调者单独记录业务任务活动或历史结论，Worker 的本轮执行、正式结束和 Issue 关闭都不决定业务任务结束。

实现采用独立 BusinessTaskLedger，按项目保存在现有 meta 存储中。它保留原始来源快照、Worker 关联及版本历史，不修改既有 ProjectLedger 的不可变成员约束。原始来源决定稳定业务身份，派单 requestId 继续只标识一次幂等操作。业务派单使用确定的分配身份恢复 Task 和默认产物目录，成员、关联、初始输入及回执在同一事务提交。

旧 Worker 没有显式关联时保持未知，不按标题、目录、Issue 或前序关系自动分组。协调者可以显式关联旧 Worker，原 Task、Thread、群、执行身份、资源和原生请求保持不变。看板只读这些事实，详情继续遵循 ADR 0022 的 Codex 历史读取约定，不增加执行历史存储或看板控制接口。
