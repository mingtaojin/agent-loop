# 任务收尾释放全部可丢弃的专属资源

2026-11-14，用户确认由项目协调者判断任务正式结束，并由 Runtime 执行和记录清理。任务专属资源集中存放或登记归属，收尾覆盖临时文件、构建产物、验收证据、已完成交付的本地文件副本，以及已经交付、被替代或明确放弃的未合并代码、工作树和本地任务分支。正式收尾不再逐项请求用户确认。

用户选择释放任务占用的空间。验收证据和未合并代码不再构成默认保留理由，也不要求为所有任务产物设置保留期。删除唯一交付物前必须完成约定交付，原始工程、用户原始资料、其他任务资源和仍在使用的资源继续受到保护。数据库保留任务内容、结果摘要、交付地址和清理回执。

本决定调整[项目协调者原规格 R12](../../.scratch/project-coordinator/spec.md#r12-安全清理任务拥有的临时资源)中的默认保留证据及未提交成果要求。普通 release_workspace 继续拒绝释放含改动或未被基线保全的工作树。正式收尾使用独立 complete_task 动作，不放宽普通释放。任务结束前的持续上下文沿用 ADR 0005，Runtime 不以执行空闲、暂停、失败或一轮回复结束推断任务完成。

任务正式结束后，后续追加工作作为新需求，由协调者创建关联的新 Task 承接。新任务引用旧任务摘要和交付地址，并独立分配资源。原 Task 保留可查询记录，不因追加需求重新启用，已删除的文件不恢复。这为 ADR 0005 的持续上下文增加正式结束边界。

清理状态持久保存，实际失败保持待清理，服务重启后可以继续。本次不扫描、补登记或回收历史任务遗留资源，仅管理启用后按新约定分配、登记的新资源。长期协调者在每次派单或核查工作结束后，清理本次产生且不再使用的临时脚本、日志和下载副本，保留项目记录及仍在使用的资源。

本决定的三个设计问题均已确认，详见[任务收尾规格](../../.scratch/task-resource-cleanup/spec.md)。本决定不授予删除远端资源或远端分支、解散任务群及停止运行服务的新权限。

2026-11-14 实施采用独立的 Task closeout SQLite 账本。业务结束与冻结清理意图在同一事务保存，避免旧 Task 执行快照覆盖结束结论。操作回执只保存稳定句柄，实时结果从账本读取。新目录记录物理身份，完成后的只读使用探测不恢复 Thread。工具参数和限制见[任务收尾](../task-closeout.md)。

Runtime 收尾验收使用真实 SQLite、文件、Git 和子进程。模型与飞书为受控替身。原生请求协议测试覆盖结束前的未解决请求和结束后的否定响应，未知回执继续阻止清理。最终验证结果随实现记录，不由本 ADR 的接受状态表示。该验证不包含真实模型、飞书、业务任务清理或正式实例部署。
