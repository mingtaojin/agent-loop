# Agent 决定工作流程和消息含义

2026-11-05 已确认设计，尚未实现。在 ADR 0004 的职责边界上，明确由 Agent 调用澄清技能、解释用户意图并决定工作如何推进；Runtime 负责消息投递、会话关联、通用执行与等待、持久化和恢复，不编排 grill 与开发阶段，不把草稿 PR 作为固定交付条件。

任务群的新消息应立即追加给正在运行的 Agent，包括要求停止的消息；Runtime 不依据消息文本截获或决定暂停。没有活跃执行时，新消息在原会话发起一轮；讨论回答后等待，无新输入不自行续跑。已明确交办的工作由 Agent 持续推进，不以固定短周期切轮代替 Agent 自主执行。

工程指导采用技术 Bug 自主定位、修复和验证，仅在业务含义不明确或授权不足时停下相关工作并澄清；已确认授权不重复询问。这属于 Agent 的指导，替代旧 Bug prompt 中每次实机复现后必须等待人工确认的固定步骤，不转化为 Runtime 的业务状态机。

收集条件只决定是否创建新任务；任务创建后，Issue 关闭、分配或标签变化作为信息交给原任务的 Agent，由 Agent 判断对工作的影响，Runtime 不再直接暂停任务。此决定取代 ADR 0002 中来源不再匹配即暂停、必须明确恢复的规则。

已关联到 Task 的有效外部事件，运行时追加，空闲时唤醒原会话。Runtime 负责来源校验与去重，Agent 判断事件对工作的意义；唤醒不代表尚未收到的人工答复或授权已被补齐。此决定也取代旧版规格中等待任务只通知来源更新、不唤醒会话的规则。

Runtime 及时转发 Agent 面向用户的进展说明和最终答复，不默认逐条发送原始工具日志，也不自行判断工程阶段或编写工程总结。原生工具审批通过绑定具体请求的独立批准/拒绝操作转接；普通群消息继续投递 Agent，不由 Runtime 解释为权限批准。具体飞书交互控件和回调仍需技术验证。

2026-11-06 更新：按用户要求，任务群只转发 Agent 的最终答复，中间过程说明保留在本地调试台。此约定取代上文同时转发进展说明和最终答复的规则。原生问题、工具审批和服务异常提示继续通过飞书发送。

2026-11-07 更新：用户确认在任务群中增加动态执行进度卡片。启用后，每轮执行使用一张持续更新的卡片，展示执行状态、面向用户的模型文字和最近的工具输出，并提供可配置的完整日志入口。更新合并发送，输出长度有界；最近活动时间来自实际执行事件。最终答复继续独立发送，原生问题和工具审批保留原有通道。进度投递消费已有执行记录，持久化卡片身份和更新顺序，飞书更新失败不改变任务执行状态。此决定取代上一条仅在调试台展示中间过程的限制。

2026-11-07 后续更新：用户反馈卡片影响阅读聊天，并确认改用固定的“执行进度”入口。任务群通过文档标签页展示飞书云文档，文档跨轮次复用，每隔几秒合并更新执行状态、最近文字和有界命令输出。停止向聊天发送进度卡片；最终答复、原生问题和审批仍在聊天中处理。该决定取代本任务刚启用的逐轮卡片展示方式。文档更新继续独立消费执行记录，故障不得阻断任务或最终回复。
