# 协作工具由 Agent 决定调用

2026-11-20，用户确认梳理整个协作工具层，包括创建 Worker、建群、双向消息、群公告、任务结束和清理。Agent Loop 提供工具，由 Agent 判断调用时机与工作推进方式。十项行为决定及验收场景见[规格](../../.scratch/agent-collaboration-tools/spec.md)。本决策已用于协作工具实现，运行实例启用另按实际部署授权执行。

Agent Loop Worker 仍仅由协调者创建。Worker 使用 pstack 组织内部子 agent，不将这些子 agent 注册成独立的 Agent Loop Worker。

Agent 消息只在协调者与其项目内 Worker 之间双向传递。Worker 之间不直接通信，跨任务交流经协调者处理。这保留了协调者作为项目任务组织者的边界。

Worker 可以自行调用工具为自己建立任务群，已有群则复用。协调者仍可为 Worker 建群，何时需要建群由 AI 判断。此决定改变现有 `open_group` 仅允许协调者调用的限制。

Agent 间通信和面向人的群消息采用两个独立工具。前者将内容交给接收 Agent 处理，后者将内容发送到群里供人阅读，两者不互相替代。Worker 群保留类似 Codex CLI 的默认体验，自动展示完整助手过程说明、问题和最终回复；协调者自行选择需要发到协调群的内容，并调用群消息工具发送。内部协作消息不自动转发到协调群。本决定调整 ADR 0017 按输入来源决定协调者普通回复是否进群的规则，保留 Worker 群已有的默认输出行为。

统一协作消息发送后即可投递给接收者处理，不等待发送者本轮成功结束。发送者自行判断发送时机，后续失败不撤回已送达消息，情况变化通过后续消息说明。这选择了直接交流的语义，放弃 ADR 0024 对成果通知等待匹配轮次成功结束的约束。

提供一次性的定时自我唤醒工具，由 AI 设置时间和提醒内容。未设置时不产生定时提醒，Runtime 不固定轮询催办。到期提醒使用已有任务输入机制，正在执行时追加输入，空闲时开始一轮。暂停任务沿用现有持有输入的行为，消息和到期提醒均不自动解除暂停。

任务结束与文件清理分为独立工具动作。结束任务只记录结束状态，不同时安排资源删除；AI 另行调用清理工具。这样可以在工作完成后保留现场供复查，代价是未调用清理时文件继续占用空间。本决定取代 ADR 0016 中正式结束任务即安排资源清理的目标契约。

已结束任务收到新消息后，可以唤醒原 Worker 并沿用原上下文继续处理。任务结束表示当前约定工作完成，不再永久禁止原任务继续执行。是否另建任务由协调者根据工作内容判断。这取代 ADR 0016 中后续新增工作必须创建关联新任务的约束。清理与资源使用不能并发，已删除文件不因继续会话而被视为仍然存在。

删除派单工具中对 Feature 开发授权消息、Issue 版本和调查模式的业务检查。协调者依据 prompt、实际用户指示和上下文判断授权是否充分、需要调查还是实现，并将范围写入 Worker 任务说明。ADR 0018 中关于外部提案和用户授权的业务指导由 prompt 承载，工具不再要求用特定群消息及业务字段通过检查。删除检查不意味着外部提案自动构成用户授权。

本决策延续 ADR 0006 的职责划分。业务规则放在 prompt，Runtime 负责身份和目标校验、可靠投递、持久化恢复以及实际资源约束。已确认的角色和通信边界仍由工具执行。现有任务、Thread、群和执行身份在迁移中保留，服务启用另按实际操作授权执行。
