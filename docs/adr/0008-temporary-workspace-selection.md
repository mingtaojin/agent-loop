# 工程入口选择使用独立临时会话

2026-11-14：[ADR 0015](0015-shared-local-codex-app-server.md) 已确认正式任务和工程入口选择共用本机 Codex 服务，替换本文的独立 App Server 进程要求；独立临时 Thread 及其上下文和权限边界继续适用。该后续决定尚未实现，以下保留原决策及其依据。

2026-11-06，用户要求目录仍由大模型选择，但选择过程与正式任务分开，并明确两者不应使用同一个 Thread。新任务先用独立的只读临时 Thread 判断工程入口，Runtime 校验并保存结果、准备工程资源后，另建正式 Thread。这样正式任务接收确定的执行环境，临时模型的选择过程不进入持续的任务会话。

选择会话只接收专用选择指导、配置的候选工程入口和原始任务材料。任务材料用于判断目录，不能在这一阶段触发正式调查、实现、poteto-mode 或 grill-with-docs 工程工作。模型可以选择配置中的仓库、无需工程目录，或请求用户补充目录信息；Runtime 不根据来源类型或关键词代替模型做选择，也不接受候选范围外的任意目录。

选择结果经校验后先保存，再通过现有工作区管理器准备共享项目目录或独立 Git worktree。正式 Thread 使用准备好的工程目录作为实际工作目录；无需工程目录时使用任务资料目录。正式 Thread 接收统一业务指导、简短环境说明和完整原始任务与附件，保留原来源身份，不复制临时会话历史。准备目录不授予额外修改、部署或工具权限。

目录问题的所有者答复单独保存并用于下一次选择。下一次选择创建新的临时 Thread，依据原始材料和已保存答复重新判断。用户答复也作为正式任务的用户补充，按原顺序保留完整文字、来源与附件。原始任务和这些补充一起进入正式 Thread 的首轮输入，确保“用 A 目录，但只排查、不要改代码”等限制在执行前可见；临时模型的问题、推理与选择输出不进入正式上下文。外部来源更新不能冒充用户答复。等待答复时不创建正式 Thread，服务重启保留问题和等待关系。

目录选择是否已使用某条用户答复，与该消息是否已投递到正式 Thread 分别记录。首轮合并投递保留每条原消息的投递身份；回执丢失后逐条依据正式历史核对，不重复选择或盲目重发。

选择侧可以单独配置模型（`codex.selectionModel`），与正式 Thread 的模型解耦；只读、无审批、无动态工具和选择后释放进程的边界不变。未配置时两侧使用同一模型。

每次选择使用独立的临时 App Server，只读 Thread 在选择完成或失败后随该进程释放。选择失败有限恢复，服务关闭中止选择并释放进程。重启后复用已保存且有效的选择结果；尚未完成的临时选择可以依据保存材料重做，不恢复临时会话的模型历史。正式 Thread 创建和输入投递仍遵循现有结果未知时不盲目重放的约定。

一旦正式 Thread 已建立，后续讨论、澄清、工程执行与恢复继续使用它，不重新进入目录选择。正式任务仍可通过现有 `ensure_workspace` 动态工具申请额外工程资源，新正式指导不再携带选择流程和备用 shell 命令。已有正式 Thread、工作区与分支保持原样，旧 Thread 的工作区兼容入口继续保留；历史上仍未建立正式 Thread 的任务进入新的选择流程。

本决策调整 [ADR 0005](0005-task-as-continuous-context.md) 中新任务建立正式会话的时机，并扩展 [ADR 0007](0007-project-directory-workspaces.md) 的工程入口准备方式。Task 可以从普通讨论开始、无需工程目录，以及同一 Task 可涉及多个仓库的原则保持不变。[ADR 0006](0006-agent-owns-workflow-and-message-intent.md) 中由 Agent 决定业务工作流程的边界也保持不变，目录准备不引入业务访谈或开发阶段编排。
