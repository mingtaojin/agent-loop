# 协调群只展示允许的用户可见消息

2026-11-14，用户确认项目协调群应保持可读。GitHub Issue、评论和由其派生的接单请求继续进入协调者 Thread，但不应因为每个后台事件都产生一条普通群消息。Worker 和 verifier 的 `report` 同样先交协调者判断，不直接刷项目群。

项目协调群的可见消息采用正向白名单：

- 用户在项目协调群直接发送消息后，协调者的普通最终答复继续显示；
- 协调者通过 `announce` 明确发送的协调群公告显示；
- 原生问题、审批、权限请求以及 Runtime 明确的系统异常继续使用现有通知通道。

GitHub 自动事件、GitHub 派生的 `intake_request`、Worker 或 verifier 的普通 `report`，以及它们触发的协调者普通最终答复只保留在协调者 Thread、执行记录和进度文档中。它们需要用户处理时，由协调者调用 `announce`，而不是依赖普通最终答复自动出现在群里。

`announce` 只允许项目协调者调用，使用稳定 `requestId` 并遵循现有项目动作的幂等和内容冲突规则。动作携带公告类型和正文：

- `decision`：需要用户决定；
- `blocker`：任务阻塞；
- `approval`：需要用户处理审批相关事项；
- `delivery`：明确交付结论。

公告以带类型标题的普通文本发送到项目协调群，不新增飞书卡片或回复线程能力。类型标题分别为“需要决定”“任务阻塞”“需要处理审批”和“交付结论”。公告正文是用户可见的完整内容。公告成功后，同一轮协调者普通最终答复不再重复发送到群，但仍保留在 Thread 和执行记录中。

本决策调整 [ADR 0006](0006-agent-owns-workflow-and-message-intent.md) 中“协调者最终答复及时转发”的范围：项目协调者的用户触发答复仍自动转发，后台事件触发的普通答复改为内部记录，用户可见内容通过明确公告产生。原生审批和 Runtime 异常通知不因本决策改变。

该设计不改变 GitHub 收集、项目记录、Worker 汇报、Thread 恢复或进度文档的保存范围。它只改变项目协调群的投递入口，避免后台 Issue 数量增长直接扩大聊天噪声。
