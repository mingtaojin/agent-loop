# 项目任务按需建立飞书群

每次委派都建群使用户注意力分散。2026-11-13，用户选择通过项目协调者处理日常交互，Worker、verifier 和 intake 默认无任务群。项目协调群继续保留。该决定取代 ADR 0001 的每任务必有群约束。历史任务按原身份纳入项目协调。

用户需要直接与某个任务代理交流时，向协调者用自然语言提出，由协调者识别本项目任务并打开群。原生审批需要按钮时，Runtime 按需建群并在项目群通知一次。普通提问和最终输出交给协调者，无群期间不积压飞书消息。新群只发送欢迎与当前摘要，不重放旧消息。

2026-11-14 更新：用户要求保留 Worker 群的本地讨论，取代上文自动传递普通最终输出的约定。Worker 和 verifier 的普通最终答复、任务群内用户消息不再自动送给协调者。正式工作问题、阻塞、进展和成果使用现有 `report`，独立任务完成也须主动汇报。直接群内澄清继续在本任务进行，不因需求尚未确定而自动汇报。

用户明确要求同步后，由 Worker 直接 `report update` 发送当前讨论摘要，无额外预览。摘要包括结论、范围变化、待决问题和证据，保留实际用户消息、群和发送者来源，按用户指定话题限制范围。自然语言理解和摘要归 Worker，Runtime 不新增命令解析、同步任务或聊天模式。汇报仍是代理来源，不增加实施、合并、部署或原生审批授权。

协调者依真实事件核查工作。移除定时监督提醒，没有新事件时持续等待；静默本身不证明失败。原生问题、审批、权限请求、失败、非暂停中断、GitHub 更新、项目群用户输入及必要生命周期事件保留。轮询只观察和投递已有事件。该选择复用既有 Task、Thread、持久 inbox 和汇报回执，避免普通对话结束被误作正式交付。

历史合法监督间隔仅在显式配置和持久 catalog 输入边界接受并移除。已确定未投递且身份匹配的旧自动副本保留 payload 和原因，标为终态 `dropped`。已送达记录不变；已尝试投递的 `delivering` 和 `uncertain` 沿用已见输入对账，不声称撤回或重新发送。

任务上下文与任务群分开存续。手动解散或失效的群会解除关联，任务、Thread、待审批和原始记录仍然保留。再次建群使用新代次，避免复用被解散群的创建身份。按需群不自动解散。

既有任务群通过冻结清单一次确认后批量清理，始终排除所有项目协调群。解散会删除飞书聊天记录，因此执行必须保存实际用户对该清单的确认。每个群的结果单独保存，未知结果先核对再继续；权限错误停止本批。部署并确认清单之前不执行清理。
