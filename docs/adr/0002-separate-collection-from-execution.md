# 收集 Issue 与启动处理分离

2026-11-05：下文中“来源不再匹配即暂停并等待明确恢复”的设计已被 [ADR 0006](0006-agent-owns-workflow-and-message-intent.md) 取代；实现尚未调整，其余历史决策保留。

2026-11-05：新版[首版规格](../../.scratch/agent-runtime-context/spec.md)已确认移除只允许 Bug 的硬编码，由配置决定纳入类型；下文首版 Bug 范围是旧版历史，不再作为 Runtime 的固定类型限制。

收集组件按配置条件同步 GitHub Issue 并保留来源和描述，核心循环负责安排执行。首版筛选为分配给目标用户的未关闭 Bug；仓库、分配人、类型和标签等条件可配置。匹配后自动进入处理流程，无需固定启动标签或人工启动，也不由模型判断处理价值。

职责分离使采集不必等待任务完成，也允许核心循环独立管理执行资源、等待与恢复。持久化记录成功与实际启动执行是不同事件；重复收集不应重复创建执行任务。首次纳入配置仓库中匹配条件的历史积压。

收集配置更新只影响后续纳入的来源，已有任务保存创建时的筛选条件与类型映射。来源本身变化使其不再匹配原条件时暂停并通知，保留任务关联，等待明确恢复；由此区分用户调整采集范围与上游改变具体工作的情形。
