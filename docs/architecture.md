# 持续上下文 Runtime

Task 是一件事情的持续上下文，对应一个飞书任务群和一个 Codex Thread。Agent 决定工作意图、技能、澄清及交付。Runtime 保存和传递输入，管理原生执行、等待、输出及故障恢复。本文描述当前实现，设计边界来自 ADR 0005、0006 和 0007。

## 模块

| 模块 | 责任 |
| --- | --- |
| `loop.ts` | 来源收集、会话绑定、任务内串行投递、请求与输出转发、有限恢复 |
| `store.ts` | SQLite 迁移、单实例所有权、输入与输出、审批操作和未知结果记录 |
| `domain.ts` | 人工与 GitHub 来源、资源、原生请求、输出和输入出处 |
| `adapters/codex.ts` | App Server 连接、Thread、Turn、原生问题与审批、动态工作区调用 |
| `adapters/feishu.ts` | 私聊和群消息、任务群、附件、历史、认证审批卡片 |
| `adapters/github.ts` | Issue 与评论分页、稳定来源身份 |
| `workspace.ts` | 获取独立 Git worktree 或共享项目目录，核对持久化关联 |
| `project-discovery.ts` | 发现父目录的一级项目入口，保存入口路径与规范路径身份，不读取 Git 信息 |
| `workspace-bridge.ts` | 为无动态工具的旧 Thread 提供任务限定的本地资源调用 |

同一 Task 的事件按串行队列处理。不同 Task 没有全局数量门槛。动态工具和本地资源调用不等待任务队列，避免执行器等待资源回调而 Runtime 等待执行器的死锁。资源按 Task 与仓库合并并发创建，同一 Git 公共目录的变更顺序执行。

## 数据与状态

`Task.source` 区分 `manual` 和 `github`。`contextDirectory` 是会话上下文目录，`resources` 可为空或包含多个仓库关联。旧任务的 Thread 与合法工作目录保持原样。迁移把旧 `waiting_user` 和 `awaiting_review` 归为 `idle`，历史状态与 PR 地址保存在 legacy 元数据。

Runtime 状态为 `pending`、`running`、`idle`、`paused`、`failed`。原生执行状态和待决请求独立保存。状态不表示调查、开发、验收或部署阶段。原生轮次完成可以没有文本，也可以有普通最终答复，不作 PR 或业务成功判断。

输入记录保存原消息、出处、顺序、投递状态和原生问题关联。来源事件没有配置用户的身份。审批动作独立持久化并绑定 Task、群、Thread、Turn、请求与连接 epoch。回调先持久化操作，后台再核对实际请求并等待原生 resolution；写出响应但未确认时标为 uncertain。

输出按稳定 AgentOutput ID 去重，只转发用户可见进展与最终答复。原始工具日志和内部推理不作为普通消息发送。旧版 `turn:<turnId>` 出站记录继续作为历史通知屏障，避免升级后重发已处理轮次。pending、sending、sent 和 uncertain 区分准备发送与实际确认。

## 输入与来源

所有者直接私聊机器人发送文字、图文、截图或日志文件即可创建任务，不需要命令前缀。每条不同的非空私聊消息各自创建一个 Task 和独立任务群，以消息 ID 去重重复投递。内容相同但消息 ID 不同的消息仍各自创建任务；空白文字且无附件的消息不创建任务。Runtime 不使用语义意图分类器决定是否创建任务，工程入口选择发生在任务创建之后。

后续输入在对应任务群继续，再次私聊会创建另一项任务。群消息始终属于既有任务，旧文本控制命令没有 Runtime 含义。普通消息只有在唯一原生问题存在时才映射为问题回复。外部事件始终作为来源事实追加，不回答问题或授予权限。历史消息补偿只读取已有关联任务群的消息。

活跃 Turn 使用 steer，空闲 Thread 使用 start。Turn 结束竞争通过重新 inspect 核对投递标识。未知投递形成屏障，不重放原输入或越过它执行后续输入。已明确失败的附件留存并报告，后续独立文字可以继续。

收集条件只决定新建来源。默认 Bug 范围保持不变，Feature 由配置启用。已有来源始终按保存身份读取，即使仓库从新配置移除。内容变化使用观察序号与内容摘要标识，既去重重复轮询，也保留 A 到 B 到 A 到 B 的每次变化。只有更新时间变化不会唤醒。评论保留 ID、作者、URL、正文及时间。

## 工作区与旧 Thread

新 Thread 注册 `ensure_workspace`。新工程资源必须属于发现的项目入口或原有显式工程配置，资源关联绑定当前 Task。GitHub 采集来源继续只由显式仓库名和收集条件决定。获取工程入口不复制或重置原始仓库的暂存、未暂存与未跟踪内容。已有分支或目录身份不符时报错，不覆盖。

`engineering.projectRoot` 提供可配置的父目录，相对路径以配置文件所在目录为基准，没有本机路径默认值。每次新的入口选择发现该父目录的一级工程目录，目录本身不要求 Git 元数据。临时模型从提供的候选中判断所需工程，Runtime 校验其身份并保存选中的目录快照，再使用已有共享目录准备逻辑建立资源。内部仓库和版本不作为独立入口。

项目入口身份与 GitHub 来源身份分别保存。恢复项目资源使用保存的入口路径与规范路径，改变发现根目录不能把同名的新目录绑定给已有任务。没有根目录的原有配置继续支持显式仓库入口，历史共享目录和独立 Git worktree 保持原来的恢复规则。

默认 `git-worktree` 资源归 Task 独立使用。显式 `project-directory` 策略返回已存在的完整工程目录，允许多个 Task 关联同一目录，不生成 Git 分支。资源种类与目录随仓库快照保存；恢复与重复申请核对原关联，不应用后来的配置迁移工作区。历史没有 kind 的资源在 schema 边界按 Git worktree 解析。共享目录失效或改指向时报错，不创建目录或重新绑定。

真实协议探针确认旧 Thread 的 dynamicTools 在 resume 时不能追加。Runtime 因此提供本地 Unix socket 与任务能力文件。客户端提交工程目标，能力决定所属 Task，Runtime 是唯一 SQLite 写入者。原有仓库请求保持兼容，发现的项目使用明确的项目身份。能力随进程更换，暂停任务和无活跃 Turn 不能调用。该入口与动态工具共享资源校验和持久化，不创建新 Thread，也不修改 Codex 内部持久化。

目录选择使用独立的临时 App Server 与只读、无审批 Thread；`codex.selectionModel` 可让该 Thread 使用与正式任务不同的模型，省略时继承正式模型。模型选择只改变推理侧配置，不改变只读、禁用工具或释放时机。

工作区路径返回不改变权限。Agent 读取项目说明，在实际 sandbox 与原生审批范围内使用目录。协议字段存在不代表目录访问已通过验证。

## 恢复

启动先取得数据目录独占所有权并迁移数据，再核对已有群、资源、会话和离线消息。来源读取失败保留诊断，不阻断已关联用户会话。资源身份失败保持 failed，不进入可能绕过身份核对的传输重试。

执行适配器合并并发传输恢复，替换连接并使旧请求 epoch 失效。Runtime 对已确认中断或失败的执行按配置有限续接，先核对输入和旧执行。正常完成、原生等待及显式操作员暂停不因重启自动推进。旧版暂停任务收到新的所有者消息可恢复普通会话。

输出发送、审批响应或创建资源的结果未知时，保存证据并停止盲目重放。有限恢复不声称能自动判断任意外部业务命令是否成功。没有总时长硬限制，也不以无进展消息单独判定失败。
