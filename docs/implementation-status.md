## 当前实现

- 所有者直接私聊机器人发送文字、图文、截图或日志文件，每条不同的非空消息各自创建一个 Task 和独立任务群，不需要命令前缀。按消息 ID 去重，内容相同但消息 ID 不同仍各自创建任务。空白文字且无附件的消息不创建任务，不使用语义意图分类器筛选任务。
- 后续补充、答复和材料在对应任务群继续，再次私聊创建另一项任务。Task、群和 Thread 持续保留，工程资源按需建立。
- 历史消息补偿只读取已有关联任务群的消息，已有任务与消息记录继续保留。
- 历史消息补偿失败时不推进游标，下一次补偿重新覆盖同一区间。单次失败只写入诊断记录。连续失败时，任务群只收到一次说明，恢复后再收到补收结果。原始错误保留在诊断记录中。
- GitHub 类型由配置的分类名称和映射决定，默认仍只收集 Bug。已有 Issue 变化与分页评论进入原会话。
- 普通结果和进展直接转发。正常结束等待新输入，没有固定 JSON、PR 或实机确认门槛。
- 所有普通群文字作为输入。原生问题接收人工答案，审批卡片持久化操作后异步等待原生确认。
- SQLite 迁移保留旧会话、路径、消息与未知操作。旧历史通知不会重复转发，旧暂停任务可由新的所有者消息继续。
- 独立 worktree 支持同任务多仓库。旧 Thread 使用任务限定的本地能力入口，实际目录权限仍由 Codex 控制。
- 已确认执行故障有限恢复。未知输入、审批和输出不盲目重放。正常等待、显式暂停与静默执行不会自动续跑。

## 已补齐的真实链路

- 实际所有者私聊新建 Task 和独立群，群内后续输入持续使用原 Thread，讨论时没有工程资源。

- 专用私有 GitHub 验收仓库的 Issue 更新、评论及关闭失配进入原任务，覆盖运行中追加、空闲唤醒、重复观察、进程重启及重启后的评论续接。业务 Issue 没有被修改。
