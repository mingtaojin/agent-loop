# 仅项目群交办与按需任务群

## 已确认行为

用户希望减少飞书群与注意力分散。日常通过项目协调群交办、提问和收取成果。
Worker、verifier 和 intake 默认无群。只有用户要求直接交流，或原生审批需要按钮，才按需建立任务群。

用户于2026-11-13确认移除CLI和私聊两个外部接单入口。运维CLI、内部project_action、project-client和workspace工具保留。
GitHub收集继续作为项目协调者证据。保存的任务、Thread、材料、资源、原生请求、暂停与失败状态继续保留。
需求来源及逐次确认保存在Owner任务目录的task-groups-requirements-v6.md。本规格取代先前关于保留CLI和私聊入口的决定。

## 群生命周期

- 协调者识别本项目目标后调用open_group。只有协调者可以打开同项目Worker或verifier的群。相同请求幂等，现有有效群复用。
- 原生审批按需开群并向项目群通知一次。业务问题交给协调者，转述不等于工具权限批准。
- 无群普通输出标为dropped，不积压飞书历史。新群只欢迎并给当前摘要，不重放普通消息。
- 群解散或失效后解除绑定，不失败整个Task。保留Thread、资源和待审批，使用新generation重建。
- 核群await返回后必须再次核对绑定和generation。通知与审批卡指向同一有效群。
- 进度写入在实际SDK调用前再次检查群绑定，终止尚未发送的排队写入。不要求取消已发出的HTTP。
- 按需群不自动解散。真实群清理需要已生效代码及对冻结清单的明确用户确认。
- 批量清理保护所有项目协调群。逐群记录结果、可恢复，已不存在跳过，未知结果先对账，权限错误停批。
