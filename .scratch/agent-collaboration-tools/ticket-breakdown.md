# Agent 协作工具工单拆分

用户已确认本拆分，8 张独立工单已发布到本地 Markdown tracker，均标记为 ready-for-agent。编号 01 至 06 当前可开始，建议先完成 01。各工单链接见下表。

每张功能工单包含完整工具入口、持久状态、实际可见行为、相应 prompt 与调用方迁移，以及验证。无需单列通用基座重构；优先复用现有 Runtime 输入和恢复接缝，必要的局部预整理在所在切片开始时完成。

依赖表示行为前提。共享实现位置可能带来合并冲突，但不作为额外阻塞边。01 至 06 没有行为前置依赖，建议优先完成 01 解决主动汇报问题。07 需要 01 和 06，08 等待其余独立能力和 07；01、06 已通过 07 传递，不重复列为 08 的直接阻塞。

每个切片完成时删除自己替代的旧活跃调用并处理相关旧数据。08 负责组合验证与完整 prompt 接入，不作为推迟各切片迁移的理由。

## 01：协调者与 Worker 双向消息闭环

工单：[01 协调者与 Worker 双向消息闭环](issues/01-agent-messaging.md)。

**What to build:** 无群 Worker 可以主动把进展、阻塞和成果发给协调者；协调者立即接收并能发回指令，双方继续各自工作。

**Blocked by:** None (can start immediately)。

- [ ] 新增独立的 Agent 消息工具，协调者与其项目内 Worker 双向通信成功，无需任务群或用户先要求汇报。
- [ ] 发送者仍在运行时，接收者已经能够收到输入；运行中追加、空闲时启动原会话，后续失败不撤回已送达消息。
- [ ] 拒绝 Worker 之间及跨项目通信，不能伪造发送身份；暂停接收者保存消息，恢复后处理。
- [ ] 同一发送操作重试、丢失回执和重启后不重复投递；不确定回执通过已有机制对账。
- [ ] 状态查询能够查看发送者、接收者、内容和实际投递状态；普通 final 和文件记录不自动成为 Agent 消息。
- [ ] 同步更新工具定义、客户端入口、角色说明和动态上下文中与内部通信有关的规则。迁移所有调用方并删除旧 report 路由与 deliver_result 待交付状态机。
- [ ] 该通信切片同时处理旧报告与待交付记录。已送达内容不重发，未完成或不确定记录有明确对账结果，历史 final 不批量补发。
- [ ] 从完整 Runtime 入口验证上述行为，保留来源、隔离、去重和恢复覆盖。

## 02：独立群消息工具与两类群体验

工单：[02 独立群消息工具与两类群体验](issues/02-human-group-messaging.md)。

**What to build:** 协调者通过独立工具选择发给用户的消息，Worker 群继续自动展示完整助手交流。

**Blocked by:** None (can start immediately)。

- [ ] 向群发消息是独立工具，仅发送供人阅读的内容，不向其他 Agent 注入执行输入。
- [ ] 协调者的普通最终答复不再按输入来源自动进入群；主动发送后群里可见，包括对用户直接提问的回答。
- [ ] Worker 群保留完整助手过程说明、问题及最终回复的默认输出，普通回复无需额外调用发送工具。
- [ ] 同一次主动群投递不会被旧公告入口或最终答复转发重复发送，重试与丢失回执沿用已有去重和对账能力。
- [ ] 删除被替代的旧公告发送入口和分类要求，迁移相应调用方及动态提示。原生问题、审批、权限和系统异常渠道保持可用。
- [ ] 使用已有协调者建群能力即可独立演示本切片；验证两个群的输出、投递记录与重启后的行为。

## 03：Worker 自行建立和复用任务群

工单：[03 Worker 自行建立和复用任务群](issues/03-worker-self-group.md)。

**What to build:** Worker 需要与用户直接讨论时，自行创建任务群并开始正常交流。

**Blocked by:** None (can start immediately)。

- [ ] Worker 能为自己建立任务群，协调者仍能为自己项目内的 Worker 建群。
- [ ] 重复、并发调用或响应丢失后复用已确认的群，不制造重复任务群。
- [ ] Worker 不能为另一个 Worker 或其他项目建群，既有项目协调群不被误当作任务群复用。
- [ ] 建群后普通用户输入继续原 Worker 和 Thread，完整助手输出沿用现有 Worker 群行为。
- [ ] 更新建群能力的工具定义和相关 prompt，不再要求 Worker 先请协调者代办。
- [ ] 复用现有群创建和恢复测试，覆盖无群、已有群、创建失败和不确定回执场景。

## 04：由 Prompt 决定工作范围的 Worker 派单

工单：[04 由 Prompt 决定工作范围的 Worker 派单](issues/04-prompt-driven-dispatch.md)。

**What to build:** 协调者依据用户要求与项目规则直接派发调查或实现任务，工具不再要求业务授权字段。

**Blocked by:** None (can start immediately)。

- [ ] 删除 Feature 派单对指定群消息、Issue 版本、范围指纹和业务模式的强制检查。
- [ ] Runtime 不再按业务类型追加调查限制，协调者把实际允许和禁止范围写入任务说明。
- [ ] 只有协调者可以创建 Agent Loop Worker，完整执行配置选择、身份保持与创建去重继续有效。
- [ ] 角色和派单指导包含目标、背景、范围、已有决定、验收和交付内容；这些是写作指导，不是新的工具字段门槛。
- [ ] Worker 使用 pstack 组织内部子 agent；只讨论、只调查等用户限制继续由 prompt 和上下文指导执行。
- [ ] 同步更新所有派单入口、相关动态上下文及调用方，在完整 Runtime 测试中证明新派单契约和既有身份边界。

## 05：可取消且可恢复的一次性自我唤醒

工单：[05 可取消且可恢复的一次性自我唤醒](issues/05-scheduled-self-wakeup.md)。

**What to build:** 协调者和 Worker 可以安排一次未来提醒，到期后在原上下文继续处理等待事项。

**Blocked by:** None (can start immediately)。

- [ ] Agent 可以为自己创建、查询和取消带触发时间与内容的一次性提醒，不能替其他角色安排提醒。
- [ ] 到期提醒进入现有任务输入流程，运行中追加、空闲时开始一轮；未设置提醒时不产生周期监督。
- [ ] 提醒持久保存，重复扫描、重试和服务恢复不会重复触发同一提醒。
- [ ] 暂停期间到期的提醒被保存，不自动恢复任务，显式恢复后继续处理。
- [ ] 工具回执与状态查询区分未触发、已触发和已取消的实际结果，取消与到期并发有确定结果。
- [ ] 相关 prompt 指导 AI 根据需要安排回访和取消过期提醒，不固定要求每个任务设置相同时长。
- [ ] 在现有 Runtime 测试中控制时间，覆盖未到期、到期、取消、重启、暂停和无提醒的情况。

## 06：任务结束与资源清理独立执行

工单：[06 任务结束与资源清理独立执行](issues/06-completion-cleanup-separation.md)。

**What to build:** 协调者结束任务时保留文件，需要释放空间时再单独调用清理工具并查询结果。

**Blocked by:** None (can start immediately)。

- [ ] 记录任务结束只保存当前结论与摘要，不创建或隐式推进一项新的清理操作。
- [ ] 独立清理工具可以处理明确指定、归属清楚的任务资源，包括已结束任务的资源，不能因已结束而无法清理。
- [ ] 任务当前完成情况和清理状态可分别查询，看板不再把两者呈现为同一结果。
- [ ] 保留资源身份、归属、占用与并发检查，原始资料、共享目录和其他任务资源不被误删。
- [ ] 清理与资源使用互斥，无法立即处理的清理返回真实状态；响应丢失或重启不会重复误删。
- [ ] 同步迁移该生命周期切片的数据、调用方和 prompt。旧完成记录保持可读，升级不凭完成标记生成新的删除请求。
- [ ] 使用现有真实文件、Git 工作树、子进程和 Runtime 集成测试验收；本切片暂不改变结束后的输入续接规则。

## 07：新消息继续已结束 Worker 的原会话

工单：[07 新消息继续已结束 Worker 的原会话](issues/07-continue-completed-worker.md)。

**What to build:** 任务结束后，用户或协调者发来新消息，原 Worker 保留上下文继续处理，必要时重新准备资源。

**Blocked by:** 01 协调者与 Worker 双向消息闭环；06 任务结束与资源清理独立执行。

- [ ] 用户群消息和新的 Agent 消息均可继续原 Worker 与 Thread，不强制转给协调者另建任务。
- [ ] 继续工作更新当前完成标记或状态，同时保留之前的完成摘要、记录、群和执行身份。
- [ ] 只有暂停继续阻止自动执行；完成标记不再作为永久拒绝输入或工具调用的条件。
- [ ] 清理进行中保存输入并等待资源状态确定，不启动与清理冲突的执行。
- [ ] 文件已经清理时，原会话仍能收到消息和实际资源状态，Agent 能按需使用已有资源工具准备工作目录，不假定已删文件仍存在。
- [ ] 更新续接相关入口、prompt、状态查询和看板行为，保留是否另建任务由协调者判断的选择。
- [ ] 迁移旧完成记录后不会主动唤醒历史任务；只在实际新输入到达时按新契约处理。
- [ ] 使用真实资源验证完成后追加、清理中追加、清理后追加、暂停及重启后续接。

## 08：完整 Prompt 接入与旧实例协作验收

工单：[08 完整 Prompt 接入与旧实例协作验收](issues/08-integrated-migration-acceptance.md)。

**What to build:** 现有协调者和 Worker 使用已确认的新 prompt 与工具完整协作，真实证明主动汇报、继续推进和群消息体验。

**Blocked by:** 02 独立群消息工具与两类群体验；03 Worker 自行建立和复用任务群；04 由 Prompt 决定工作范围的 Worker 派单；05 可取消且可恢复的一次性自我唤醒；07 新消息继续已结束 Worker 的原会话。

- [ ] 将已确认的两份完整角色 prompt、项目上下文和派单说明接入新建与恢复会话，不遗留与新工具冲突的动态注入。
- [ ] 各功能切片自己的数据迁移已完成；本工单验证其组合升级保留项目成员、Thread、群、执行身份、历史记录和暂停状态。
- [ ] 检查所有实际调用入口只使用已迁移的工具，旧工具活跃调用为零；缺陷回到对应能力修复，不建立长期并行的新旧接口。
- [ ] 使用既有实例结构的隔离数据验证升级与重启，不批量重放历史 final、不重派任务、不擅自恢复暂停任务。
- [ ] 真实 Agent 场景证明无群 Worker 主动发成果、协调者收到后执行下一步，以及设置提醒后实际继续跟进。
- [ ] 在授权测试群核查 Worker 默认交流与协调者主动群发送，记录实际消息证据，不把外部替身通过算成真实验收。
- [ ] 核对全部规格验收场景，给出实际版本、完成步骤、结果与限制。环境受阻如实记录，不作为通过。
- [ ] 本工单不隐含生产部署、服务重启、远端资源删除或额外群消息授权；实际验收使用当时已授权的隔离目标。
