# 协作提示词约定

以下文件保存 ADR 0025 已确认的角色约定。生产提示词已在实现中接入具体工具名称；正文的职责划分与这些约定一致。运行实例是否启用取决于实际部署版本。

- [协调者固定提示词](coordinator.md)负责项目组织、双向通信、面向用户的消息和后续跟进。
- [Worker 固定提示词](worker.md)负责执行任务、主动联系协调者和任务群交流。

采用 Laziness Protocol，公共角色提示词只保留角色职责与协作规则。具体工程流程由 pstack 定义，单次任务约定由协调者填写。

## 每次派单提供的内容

协调者为每个 Worker 组织实际任务说明，按需要提供以下内容。它们是写作指导，不是工具强制校验的业务字段。

```text
目标：本次需要解决什么问题，交付什么结果。
背景：相关用户要求、已有任务、代码位置和资料。
范围：本次做什么、不做什么，当前允许的操作。
已有决定：已确认结论及来源，真正尚未解决的问题。
验收：如何证明完成，需要哪些运行证据。
交付：成果位置、与现有工作的关系、需要协调者继续处理的事项。
```

工具定义提供参数、返回值和调用约束。项目配置与每次输入提供项目身份、协调者和 Worker 标识、可用执行配置、项目专属规则及最新记录，公共提示词不硬编码这些值。

## 接入约束

当前 `src/loop.ts` 的 `instructions` 会组合角色文件、资源说明、`ProjectRuntime.instructions` 和已有派单内容。新设计接入时必须一起更新这些来源。

删除旧的 Worker 群用户汇报请求校验说明、report 路由分类、deliver_result 待成功结束说明，以及已结束任务必须另建任务的文字。保留历史派单里的目标和用户决定，将已经改变的 Runtime 使用说明明确更新，不能让旧规则与新规则同时注入。

旧协调者 prompt 中创建 verifier 角色的文字已删除。项目角色只有协调者和 Worker，独立验证按 pstack 和项目实际能力组织。

公共提示词、项目规则和任务说明不重复粘贴整套相同约束。已有项目规则若与新设计冲突，接入时明确指出并迁移，不能只改两个 Markdown 文件就认为已经完成。
