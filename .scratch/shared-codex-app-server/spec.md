# 正式任务与工程入口选择共用本机 Codex 服务

## Problem Statement

本机 Codex 已经提供共享 App Server。Agent Loop 仍启动私有执行服务，工程入口选择还为每次判断启动临时服务。用户希望这些客户端共用已有服务，同时保持任务对话、工程入口选择、权限和执行恢复各自的约定。

## Solution

正式任务和工程入口选择均连接本机 Codex 共享 daemon。daemon 未运行时使用官方入口启动，已运行时直接连接。连接中断后重连并核对原有执行状态，不停止或重启共享 daemon，也不回退到私有服务。

共用执行服务不合并任务上下文。正式任务保留原 Thread。工程入口选择使用独立临时 Thread，保持只读、无审批、无动态工具及选择模型覆盖。选择结束后释放自身执行与订阅，其他任务和客户端继续运行。

## User Stories

1. 作为 Agent Loop 使用者，我希望正式任务连接本机已有 Codex 服务，以便复用同一执行后端。
2. 作为使用者，我希望目录选择也连接同一服务，以便每次选择不再启动私有 App Server。
3. 作为使用者，我希望 daemon 未运行时自动启动，以便无需手动准备服务才能接单。
4. 作为使用者，我希望已运行的 daemon 保持原进程，以便不打断 Codex CLI 的工作。
5. 作为使用者，我希望连接失败明确报告，以便知道任务尚未接入而非在私有服务悄悄执行。
6. 作为任务所有者，我希望正式任务保持原 Thread，以便历史与后续回复持续对应同一事情。
7. 作为任务所有者，我希望多个任务并行使用各自的 Thread，以便消息不会跨任务投递。
8. 作为使用者，我希望选择模型只判断工程入口，以便准备阶段不会执行正式调查或修改。
9. 作为使用者，我希望临时选择保持只读且无法审批，以便原有权限边界继续生效。
10. 作为使用者，我希望临时选择历史不进入正式上下文，以便正式任务从完整原始材料和确定的环境开始。
11. 作为使用者，我希望原始附件与目录答复继续按原顺序送达正式任务，以便用户限制不会因目录选择而丢失。
12. 作为使用者，我希望选择模型配置只影响选择侧，以便正式角色保留自己的模型。
13. 作为使用者，我希望角色模型、推理强度和 provider 保留原意，以便改连接方式不会静默改变执行配置。
14. 作为使用者，我希望取消一次选择只停止该选择，以便其他选择和正式任务继续推进。
15. 作为使用者，我希望选择失败能释放自身资源，以便共享服务不会积累仍在执行的无主选择。
16. 作为其他 Codex 客户端的使用者，我希望 Agent Loop 退出时不操作我的任务，以便共享服务仍可使用。
17. 作为运维者，我希望 Agent Loop 正常退出时沿用中断己方活跃执行的行为，以便退出后不会遗留需要其工具或审批的执行。
18. 作为使用者，我希望断线后核对旧执行再恢复，以便避免重复输入和重复开工。
19. 作为使用者，我希望失效审批不被重放，以便旧连接的批准不会误用到新的执行。
20. 作为使用者，我希望 daemon 在外部重启后仍可恢复已有任务，以便服务维护不丢失持续上下文。
21. 作为运维者，我希望启动失败或协议不兼容可定位，以便无需猜测任务是否已执行。
22. 作为维护者，我希望本机控制入口可配置且不固化个人路径，以便工程可以在其他安装环境使用。
23. 作为维护者，我希望有可重复的共享服务验证，以便核对进程复用、选择回收和其他客户端不受影响。
24. 作为维护者，我希望区分受控测试、真实服务验收、Git 合并和部署，以便每项完成声明都有对应证据。

## Implementation Decisions

- 已确认共用模式作为正式执行和工程入口选择的运行方式。移除这两条业务路径中的私有 App Server 启停，不维护自动私有回退。
- Codex 适配器继续实现既有执行端口。连接实现负责官方本地控制入口、WebSocket 消息传输、初始化和连接关闭。业务调用方不接触 wire 协议或 daemon 进程管理。
- daemon 启动与连接生命周期分开。先连接已有服务，确认未运行时调用官方幂等启动入口，再连接。禁止自动 stop、restart 或 update。
- 正式执行与临时选择共享同一 daemon，但使用各自登记的 Thread 和连接范围。请求、事件、输出与工具应答只能进入其所属任务。
- 正式任务保留持续 Thread、工程资源和投递身份。临时选择采用独立临时 Thread，权限与结构化结果约定沿用。
- 临时选择完成、失败或取消时，停止其仍在进行的执行，并解除其订阅。释放连接不能代替已确认停止执行的证据。
- 正常关闭继续中断己方活跃执行并核对终态，随后释放己方订阅和连接。不得向共享 daemon 发送终止信号，不操作其他客户端的 Thread。
- 断线使本连接未确认的操作保持结果未知。重新连接后核对历史及执行状态，不盲目重放输入、审批或 Thread 创建。
- 模型、角色推理强度、选择模型及 provider 在 Thread 范围应用。旧进程启动覆盖须迁移或明确拒绝无法迁移的设置，不通过修改 Codex 全局配置实现。
- 本地入口、命令和运行参数保留在配置中，优先使用官方 daemon 发现接口，不固化本次机器的 socket 路径。
- 在并行架构探索后，选择能隐藏传输和生命周期细节的最小接口。实现不改任务存储结构，除非现有恢复约定确实需要新的持久事实。
- 更新既有工程入口选择 ADR，替换独立临时服务进程要求，保留临时会话与正式会话分离的设计。

## Testing Decisions

- 主要测试边界沿用 Codex 执行端口。通过正式任务、输入、选择和关闭等公开操作观察结果、协议请求和外部执行状态。优先复用现有适配器协议 fixture 与 Runtime 测试，不为每层创建额外替身接口。
- 测试应证明共享服务持续可用、其他客户端仍可执行、任务输入不重复、选择上下文不串入正式任务。避免把私有对象结构或调用顺序当作成功条件。
- 将已有选择测试中的子进程死亡断言改为选择执行停止、订阅解除及共享服务保留的行为证据。保留只读、无审批、无动态工具、模型覆盖与原始材料投递测试。
- 覆盖 daemon 已运行与未运行、启动失败、初始化失败、多个任务和选择并发、选择完成与取消、响应丢失、连接恢复、原生审批失效以及正常退出。
- 以受控本地共享协议服务覆盖故障与多客户端场景，避免为测试破坏正在使用的真实 daemon。
- 通过实际构建产物连接本机真实共享 daemon，执行正式任务与临时选择，核对 daemon 身份保持不变及旁路客户端可用。真实服务不执行 stop、restart 或 update。
- 旧 Thread 的模型与 provider 一致性、动态工具和输入恢复需单独覆盖。初始化握手不能代替这些行为验收。
- 独立验证者针对最终 PR head 执行验证，报告 PASS、PASS+NOTES 或 FAIL。代码变更或基线变化后，不复用不覆盖新产物的结论。

## Out of Scope

- 更改任务业务流程、权限含义、角色模型选择或工程发现规则。
- 合并不同任务上下文，将目录选择历史复制到正式会话，或以新 Thread 规避旧任务恢复。
- 管理其他客户端的任务、自动更新共享 daemon，或停止和重启共享 daemon。
- 自动回退私有服务、远端共享服务部署，以及未经本次授权的服务部署或重启。
- 整理原工作区的无关修改及合并冲突。
