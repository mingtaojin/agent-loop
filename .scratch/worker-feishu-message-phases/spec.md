# Worker 飞书群展示各阶段的助手消息

Worker 在需求讨论中可能先写出完整问题和建议，随后用最终答复概括待决事项。用户希望直接在 Worker 群里看到两段原文。

## 已确认

- Worker 任务群展示 Codex 助手消息的三个阶段：过程说明（`commentary`）、部分答复（`partial_answer`）和最终答复（`final_answer`）。
- 每条助手消息写完后立即发送完整原文。同一条消息里的多个问题一起发送，正文省略阶段标签。
- Worker 开始本轮执行时，群里立即显示「处理中」。阅读最新消息时也能看到状态，包括第一条正文出现前和两条正文之间。
- 本轮持续期间显示「处理中」。每条助手正文写完即可发送，状态随本轮生命周期更新。本轮结束且本轮应发送的正文已投递后，显示「本轮已结束」。本轮以失败或中断结束时也使用这一结束文案。
- 群内状态提示只有上述两种。执行中用户仍可发送补充消息，原生提问和审批继续通过现有入口处理。
- 项目协调群的普通助手消息沿用现有最终答复投递条件。协调群公告、原生问题和审批各有独立的投递规则。见 [ADR 0017](../../docs/adr/0017-coordinator-group-announcements.md)。
- 本需求调整 [ADR 0006](../../docs/adr/0006-agent-owns-workflow-and-message-intent.md) 中 Worker 群普通回复的可见范围。现有显式中间汇报的投递规则见 [ADR 0021](../../docs/adr/0021-worker-discussion-routing.md)。
- Worker 群状态只使用「处理中」和「本轮已结束」。

## Problem Statement

Worker 的 `commentary` 和 `partial_answer` 会进入飞书「执行进度」，但普通 Worker 群只收到 `final_answer`。用户因此看不到执行过程中的问题，也无法判断 Worker 是否仍在工作。项目协调群需要继续保持当前只发送最终答复的行为。

## Solution

在 Worker 任务群中，按 Codex `agentMessage` 完成事件逐条发送 `commentary`、`partial_answer` 和 `final_answer` 的完整正文。Worker 本轮开始时发送或更新「处理中」状态，本轮完成、失败或中断并完成应发送消息的投递后显示「本轮已结束」。协调者群继续只投递当前规则允许的最终答复。

## User Stories

1. 作为 Worker 群用户，我希望看到每条已经完成的过程说明，以便及时了解 Worker 的问题和工作进展。
2. 作为 Worker 群用户，我希望看到部分答复和最终答复，以便掌握一轮对话的完整上下文。
3. 作为 Worker 群用户，我希望正文保持原文并省略阶段标签，以便直接阅读 Agent 的消息。
4. 作为 Worker 群用户，我希望 Worker 开始后立即看到「处理中」，以便知道暂时没有正文并不代表执行已结束。
5. 作为 Worker 群用户，我希望 Worker 结束后看到「本轮已结束」，以便知道何时可以开始下一轮交流。
6. 作为 Worker 群用户，我希望失败和中断也能显示本轮已结束，以便不会把终止的任务误认为仍在执行。
7. 作为 Worker 群用户，我希望执行期间继续发送补充消息，以便保持现有的任务群交互方式。
8. 作为项目协调群用户，我希望协调群仍只收到当前规则允许的最终答复，以便控制协调群噪声。
9. 作为系统维护者，我希望重启、重复事件和发送结果未知时保持消息幂等，以便恢复过程不会重复刷屏。
10. 作为系统维护者，我希望没有任务群时不补发历史 Worker 过程消息，以便新建群不会收到过期内容。

## Implementation Decisions

- 复用现有 Codex 执行事件、任务快照、任务 outbox 和飞书发送适配器。
- 把 Worker 普通消息可见性按任务角色限制为 Worker 群。协调者仍走现有最终答复和公告白名单。
- 用现有稳定输出身份和任务状态持久化消息与状态提示，支持重启、重试和发送确认不确定的恢复。
- 对状态提示使用有限状态模型，公开文案只有「处理中」和「本轮已结束」。
- 不把原始工具日志当作普通群消息。原生问题、审批和现有执行进度入口继续使用各自通道。

## Testing Decisions

- 测试通过 Agent Loop 的真实任务、执行快照和 Feishu 端口观察群消息与状态变化。
- 覆盖三种助手阶段、开始后尚无正文、同轮多条正文、正常结束、失败、中断、重启、重复事件、发送结果未知和没有任务群。
- 覆盖协调者群仍不发送过程消息，以及 Worker 群过程消息不进入协调者。
- 断言发送给用户的消息、状态和重复次数，不断言私有方法或内部调用顺序。

## Out of Scope

- 不改变 Codex 的 phase 定义。
- 不改变协调者群的最终答复、公告、原生问题和审批规则。
- 不发送原始工具输出，也不新增阶段标签或新的复杂状态文案。
- 不新增飞书卡片或外部看板。

## Further Notes

状态提示必须让最新群消息表达当前生命周期。每条助手正文仍以独立消息保留完整内容。
