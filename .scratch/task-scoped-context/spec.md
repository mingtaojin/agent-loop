# 按任务提供项目记录与协调执行恢复

Status: ready-for-agent

## 目标

独立任务只接收与自己有关的项目资料。协调者掌握任务摘要，明确转交跨任务信息。记录更新不重新加载无关会话。协调者仅由明确事件唤醒，没有新事件时持续等待。执行故障须保留原 Task、Thread、输入、资源与审批身份。

## 已确认决定

1. 项目通用规则由项目成员共享。
2. Worker 可记录自己任务的需求、决定、进展与证据。协调者可记录和分发本项目任务资料。
3. 任务细节仅提供给所属任务及明确关联的参与者。验证者获得对应验收要求、变更和证据，不自动取得所有项目任务的过程资料。
4. 协调者接收显式 report 提交的进展、结果和阻塞摘要，需要时查询任务详情。Worker 普通对话和最终答复留在原任务，用户要求同步时由 Worker 明确汇报。跨任务信息由协调者明确转交。
5. Runtime 根据记录的结构化范围提供上下文，不按文本内容猜归属。
6. 旧记录保留原文。没有明确范围的旧记录先供协调者查询，不自动广播给 Worker。
7. 一个 Task 保留一个持续 Thread。调整信息的范围，不复制或合并任务会话。

## 记录范围与访问

记录必须能够表达项目共享、某个 Task 专属，以及仅协调者可读三类范围。记录作者与适用范围分别保存。任务关系和范围目标必须属于同一项目。

Worker 和 verifier 默认保存自己的任务记录，不能把资料写到其他 Task，也不能自行提升为项目共享规则。协调者负责写入项目共享记录和跨任务转交。查询、分页、自动上下文与工具动作返回均使用同一可见性规则，防止从其他入口读到被过滤的资料。

相同记录 key 可以出现在不同任务内。更新必须命中范围与 key 的组合，不能覆盖另一个任务的同名记录。请求回执继续保证重试幂等。历史记录兼容读取不扩大其适用范围。

范围限制作用于后续提供的资料。旧 Thread 已经收到的内容仍在其历史中，本改动不删除或重写会话历史，也不把上下文筛选宣称为文件系统隔离。

## 上下文更新

角色指导、项目规则、工具与授权边界作为稳定指令。持续变化的记录按可见性组成有界的任务上下文，在任务输入或会话继续执行时提供。

更新 A 的任务记录不能使 B 的指令、上下文或 Thread 加载状态变化。项目通用规则变化只影响该项目。进行中的更新不能重放原消息、自动回答原生审批或产生重复工具副作用。新建、恢复、轮换与后续输入均遵守相同规则。

## 事件触发与暂停

2026-11-14 合入 main 的 PR #28 明确移除定时监督。这一较新的业务决定取代本规格早期的“保留定时监督并增加项目监督暂停”方案。早期监督 action、项目状态、可推进成员判断和 superseded inbox 状态仅存在于未部署分支，本次直接删除，不保留兼容层。上述现场 timer 诊断仍是历史证据，不描述最终架构。

协调者只处理显式 report、原生问题与审批、执行失败和非暂停中断、GitHub 更新、项目群用户输入及必要生命周期事件。普通 Worker 用户消息和 Worker/verifier 最终答复不自动转发。用户明确要求同步讨论时，Worker 通过现有 report 提交含真实来源的摘要，不增加授权。轮询仅观察执行和投递已有输入，不生成新的工作理由。

保留 Task 的暂停与恢复、未知投递核对以及原生审批身份。新事件不能强制恢复已暂停 Task。当前配置没有监督间隔，严格输入兼容入口仅验证并移除历史合法间隔字段，其他未知设置仍拒绝。

历史自动 owner-input、final-answer 和监督副本只有在身份与来源匹配且确定尚未投递时，才保留内容和原因并标为 dropped。delivering、uncertain 和已投递历史保留，不能当作撤回、已送达或允许重发的依据。退役规则沿用 PR #28。

## 检查与故障恢复

活动状态和动态工具请求校验不得以读取全部历史为前提。输入投递、未知结果和重启恢复仍需完整、可信的历史核对。检查优化不能把未确认的输入标成已投递，也不能把仍有审批或历史尚未可见的执行当作完成。

单个请求超时不应直接终止所有正在工作的会话。需要重建公共传输时，恢复不能因一个缺失或不可恢复的旧 Thread 阻止其他合法任务。恢复优先服务实际待处理输入和活动工作，保留原有暂停与故障状态。不得盲目重发结果未知的操作。

## 验收

- A、B 两个独立任务和 verifier 并存时，A 的专属记录不会出现在 B 的自动上下文、记录分页或动作返回中。
- 项目通用记录可见于本项目成员，其他项目不可见。Worker 自行写入其他 Task 或项目共享范围被拒绝。
- 同名 key 在不同 Task 不相互覆盖。范围、请求身份和回执在重复调用、重启与会话轮换后保持一致。
- 无范围历史记录不进入 Worker 上下文，协调者仍可查询其完整原文。
- 保存记录不触发无关会话的 thread/resume。稳定运行中的工具校验不读取完整历史。
- 已投递、结果未知、原生问题和审批的既有测试继续通过。
- 时间流逝和重启不生成监督输入或额外 Turn。普通对话不唤醒协调者，显式汇报和既有原生事件仍投递。
- Task 暂停与未知投递语义保持，历史自动副本只按原身份和确定未投递条件退役，delivering 或 uncertain 输入的内容、状态和结果未知证据不变。
- 单个超时或缺失 Thread 不使其他健康任务的执行通道永久失效。保留身份并避免重复副作用。
- 在隔离 Runtime 和本地协议子进程中复现旧行为并验证修复。真实业务实例不因验证而改变。
- 类型检查、构建、相关测试和完整测试通过。独立验证者对最终 PR head 出具可复查结论后合并。
